# Bobac Demo 工作空间说明

`/workspace/demo_ws` 是课程配套的 ROS2 示例工作空间，用来演示 Bobac 机器人在仿真环境中的导航、感知、抓取和基础控制流程。

这个工作空间只提供教学用的基础示例，重点是帮助理解各功能模块之间的数据关系和运行方式。具体实验步骤请配合课程文档使用。

## 工作空间结构

```text
/workspace/demo_ws
├── src/                         # ROS2 源码目录，所有功能包都放在这里
│   ├── nav2_demo_pkg/            # 导航功能示例包
│   ├── grasp_demo_interfaces/    # 抓取示例自定义 Action 接口包
│   └── grasp_demo_pkg/           # 抓取放置功能示例包
├── build/                       # colcon build 生成的中间编译文件
├── install/                     # 编译安装后的包文件、启动文件、配置文件和环境脚本
├── log/                         # 编译和运行过程中生成的日志
└── grasp_demo_debug/             # 抓取感知示例生成的识别文本、分割图和标注图
```

通常只需要关注 `src/` 下的功能包内容。`build/`、`install/` 和 `log/` 都是编译或运行时自动生成的目录。

## 功能包结构

### `nav2_demo_pkg`

`nav2_demo_pkg` 是导航功能示例包，用于演示 Bobac 在仿真地图中的建图、定位、代价地图、路径规划和基础导航流程。

```text
src/nav2_demo_pkg
├── config/                       # Nav2 参数文件目录，包含 AMCL、代价地图、规划器、控制器、行为树导航等配置
├── launch/                       # 导航实验启动文件目录，用于启动建图、定位、代价地图、规划测试和导航测试
├── maps/                         # 地图文件目录，保存 map.yaml 和对应的地图图像
├── rviz/                         # RViz 配置文件目录，用于不同导航实验的可视化显示
├── scripts/                      # 导航实验辅助脚本目录，例如保存地图、发送目标、触发规划请求等
├── CMakeLists.txt                # CMake 类型 ROS2 包的构建配置文件
└── package.xml                   # ROS2 包描述文件，声明包名、依赖和构建类型
```

### `grasp_demo_interfaces`

`grasp_demo_interfaces` 是抓取示例中使用的自定义接口包，用于定义不同模块之间通信所需的 Action 接口。这个包本身不负责识别、规划或控制逻辑，只提供统一的通信接口。

```text
src/grasp_demo_interfaces
├── action/                       # 自定义 Action 接口定义目录，用于描述识别、规划、夹爪控制等过程的请求、反馈和结果
├── CMakeLists.txt                # 接口生成相关的构建配置文件
└── package.xml                   # ROS2 包描述文件，声明接口生成依赖和运行依赖
```

### `grasp_demo_pkg`

`grasp_demo_pkg` 是抓取放置功能示例包，用于演示机械臂观察位姿、YOLOE 视觉识别、深度定位、TF 坐标转换、基础机械臂动作和夹爪控制流程。

```text
src/grasp_demo_pkg
├── config/                       # 抓取示例参数文件目录，集中管理相机话题、识别参数、坐标系、机械臂和夹爪配置
├── grasp_demo_pkg/               # Python 源码目录，存放抓取示例中的 ROS2 程序实现
├── launch/                       # 抓取实验启动文件目录，用于启动观察、识别、深度定位、TF 转换、规划和夹爪演示
├── resource/                     # Python 类型 ROS2 包的资源索引目录
├── weights/                      # 视觉识别模型权重目录，用于 YOLOE 相关识别示例
├── package.xml                   # ROS2 包描述文件，声明包名、依赖和运行所需组件
├── setup.cfg                     # Python 包安装配置文件
└── setup.py                      # Python 类型 ROS2 包的构建与入口配置文件
```

这个包中的程序用于展示抓取任务的关键环节，但不会直接给出完整比赛任务的最终解法。参赛者需要在理解示例流程的基础上，自行完成更可靠的感知、规划、执行和异常处理逻辑。

## 依赖说明

本工作空间依赖 ROS2 Humble 环境，并默认在已经配置好 Isaac Sim 通信环境的 ROS 容器中运行。依赖可以分为三类：

| 类型 | 作用 | 主要依赖 |
| --- | --- | --- |
| ROS2 基础依赖 | 支持节点、话题、Action、TF、消息通信和启动文件 | `rclpy`、`rclcpp`、`geometry_msgs`、`sensor_msgs`、`nav_msgs`、`tf2_ros`、`launch_ros` |
| Nav2 相关依赖 | 支持建图、定位、代价地图、路径规划、控制和 RViz 可视化 | `navigation2`、`nav2_bringup`、`nav2_msgs`、`nav2_amcl`、`nav2_map_server`、`slam_toolbox`、`rviz2`、`nav2_rviz_plugins` |
| 抓取感知依赖 | 支持图像转换、视觉识别、深度定位和数值计算 | `cv_bridge`、`python3-numpy`、`python3-opencv`、`ultralytics` |

其中，ROS2 包依赖主要写在各功能包的 `package.xml` 中，可以通过 `rosdep` 安装：

```bash
cd /workspace/demo_ws
rosdep install --from-paths src --ignore-src -r -y
```

YOLOE 识别示例还需要 Python 推理库和模型权重文件。模型权重已经放在：

```text
src/grasp_demo_pkg/weights/
```

如果运行识别示例时提示缺少 `ultralytics`，需要在当前 ROS 容器的 Python 环境中安装对应库。


### 安装 Python 依赖

本项目使用 YOLOE 进行物体检测，需要安装相关 Python 库。

1. **更新 pip**

```bash
python3 -m pip install --upgrade pip
```

2. **安装 Ultralytics YOLOE**

```bash
# 安装 Ultralytics（包含 YOLOE）
python3 -m pip install -U ultralytics
```

3. **安装 NumPy 和 OpenCV**

```bash
# 注意：必须使用 NumPy < 2.0，因为 ROS2 Humble 的 cv_bridge 不兼容 NumPy 2.x
# 同时需要降级 OpenCV 到兼容 NumPy 1.x 的版本
python3 -m pip install "numpy<2.0" "opencv-python<4.10.0"
```

4. **安装 OpenAI CLIP**

```bash
# YOLOE 需要 CLIP 进行某些功能
python3 -m pip install -U openai-clip
```

5. **安装 PyTorch**

先检查 CUDA 版本：

```bash
nvidia-smi
```

查看输出右上角的 `CUDA Version: X.X`，再选择对应的安装命令。

CUDA 11.x 可以使用 cu118 版本：

```bash
python3 -m pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu118
```

CUDA 12.x 可以使用 cu121 版本：

```bash
python3 -m pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu121
```

如果没有 NVIDIA GPU，可以安装 CPU 版本，但推理速度会比较慢：

```bash
python3 -m pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cpu
```

安装后验证 PyTorch：

```bash
python3 -c "import torch; print(f'PyTorch: {torch.__version__}, CUDA available: {torch.cuda.is_available()}')"
```

也可以进入 `https://download.pytorch.org/whl/` 查看是否有适合当前 CUDA 版本的安装包。

一般来说：

```text
CUDA 11.x 用户：安装 cu118 版本
CUDA 12.x 用户：安装 cu121 版本
不确定 CUDA 版本时：优先尝试 cu118 版本
```

6. **验证 Python 依赖**

验证 Ultralytics：

```bash
python3 -c "from ultralytics import YOLOE; print('Ultralytics OK')"
```

验证 NumPy 版本：

```bash
python3 -c "import numpy; print(f'NumPy version: {numpy.__version__}')"
```

正常应显示 `1.x.x`，不是 `2.x.x`。

验证 PyTorch 和 CUDA：

```bash
python3 -c "import torch; print(f'PyTorch: {torch.__version__}'); print(f'CUDA available: {torch.cuda.is_available()}')"
```

如果使用 GPU，正常应显示 `CUDA available: True`。

验证 OpenCV：

```bash
python3 -c "import cv2; print(f'OpenCV version: {cv2.__version__}')"
```


此外，`demo_ws` 中的 ROS 程序需要从 Isaac Sim 获取机器人、相机、雷达、TF 和关节控制接口等仿真数据。因此运行实验前，还需要先在 Isaac Sim 侧加载对应的 Bobac 场景资产。

## 环境配置

进入工作空间：

```bash
cd /workspace/demo_ws
```

设置 ROS 话题空间：

```bash
# 设置指定的 ros 话题空间（DOMAIN_ID），默认 bobac 接收发送话题空间编号为 44，可自行设置别的空间，但需要更改资产的 actiongraph
export ROS_DOMAIN_ID=44
```

如果需要手动加载 ROS 环境，可以执行：

```bash
source /opt/ros/humble/setup.bash
```

## 编译工作空间

在 `/workspace/demo_ws` 下执行：

```bash
colcon build --symlink-install
```

编译完成后加载当前工作空间环境：

```bash
source install/setup.bash
```

如果只修改了某一个包，也可以只编译指定包：

```bash
colcon build --symlink-install --packages-select <package_name>
source install/setup.bash
```
